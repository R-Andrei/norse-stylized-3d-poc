## MG-R6A — Contained-patch ownership-transfer feasibility

MG-R6A is the first functional overlap-ownership experiment after the refactor. It remains clone-only and does not remove a live patch, clip a replacement face, change a plan, or enable geometry commitment.

Production/shared code now performs the contained-candidate decision directly from geometry and provenance:

```text
group successful patch triangles by PatchLoopIndex
build render-faithful replacement/bevel face geometry
classify the same boundary-aware overlap used by the baseline census
retain only PatchContainedInReplacement loops
require exactly one containing replacement face that shares an authoritative boundary segment
store loop/owner provenance in ChamferBuildArtifacts
```

The overlap predicates and render-faithful face helpers are shared production utilities. The diagnostic wrapper still applies the same classification to the baseline counters, preserving the established `overlap=` meaning. Production does not read diagnostic counters or results.

The diagnostic harness tests direct ownership transfer by omitting one candidate patch from a cloned complete live patch set. A candidate resolves only when:

```text
the deterministic owner already contains every patch-boundary segment
every omitted patch boundary remains exactly two-use
no new expected-source-boundary failure is introduced
no new unexpected open edge is introduced
non-manifold count does not increase over the existing clone baseline
T-junction count does not increase over the existing clone baseline
```

Normal output adds:

```text
contained=candidates/resolved/stillRequired/ownerAmbiguous/boundaryTransferFailures/topologyFailures
```

`candidates = resolved + stillRequired` and `stillRequired = ownerAmbiguous + boundaryTransferFailures + topologyFailures` are required. Ambiguous candidates remain unresolved. A direct-boundary failure proves that simple patch deletion is insufficient and that an owner-face repartition or constrained triangulation is required. Existing corrected-clone construction, overlap totals, sector ownership, sliver lineage, blockers, live output, and `geometryCommit=disabled` remain unchanged.

## MG-R6B — Contained replacement-owner repartitioning

MG-R6B implements the operation proved necessary by MG-R6A. It does not omit a patch and does not alter live provisional records. For each contained candidate, the diagnostic harness:

```text
retained patch surface
+ original replacement-owner boundary
+ reversed authoritative patch boundary
-> split planar boundary arrangement
-> cancel shared owner/patch segments
-> trace residual owner cycles
-> deterministic residual triangulation
```

The arrangement is constrained to the already-proven `PatchContainedInReplacement` candidates. Proper interior boundary crossings are rejected rather than generalized into the later partial-overlap problem. Exact owner vertices and patch-boundary endpoints are protected from collinear removal. This preserves the incidence needed by neighbouring replacement/bevel faces and by the retained patch.

Individual candidates are terminally classified by the compact field:

```text
containedRepartition=
candidates/resolved/arrangementFailures/triangulationFailures/
areaFailures/boundaryFailures/topologyFailures/overlapRemaining
```

The required reconciliation is:

```text
candidates = resolved + arrangementFailures + triangulationFailures
           + areaFailures + boundaryFailures + topologyFailures
           + overlapRemaining
```

Every constructed candidate must conserve owner area, give every authoritative patch-boundary edge two uses in the transformed clone, introduce no new unexpected open or source-boundary failure, not increase non-manifold or T-junction counts over that mass's baseline, and remove the target patch/replacement overlap.

All individually resolved candidates are then grouped by original owner and rebuilt together. The second compact field is:

```text
containedCombined=
attempted/applied/ownerConflicts/topologyFailures/remainingOverlaps
```

This combined pass is evidence only. It prevents multiple contained patches sharing one owner from appearing valid solely because they were tested separately. The live builder, rendered faces, existing corrected-clone proof, blockers, and `geometryCommit=disabled` remain unchanged.

Unity validation of MG-R6B produced:

```text
containedRepartition=22/0/0/0/0/22/0/0
containedCombined=0/0/0/0/0
```

All 22 candidates therefore passed arrangement construction, residual triangulation, and area conservation, then stopped at the exact two-use boundary gate. Because that gate ran before topology and overlap checks, MG-R6B did not establish whether the subtraction removed the overlap or whether the failure was exact-key segmentation versus a real adjacent-face T-junction.

## MG-R6B.1 — Contained boundary-incidence decomposition

MG-R6B.1 keeps the MG-R6B construction unchanged and replaces the opaque boundary boolean with a clone-only incidence audit. Each authoritative retained-patch segment is classified from:

```text
exact total uses
patch uses
residual-owner uses
other replacement uses
bevel uses
other patch uses
collinear subsegment coverage
whether the segment lies on the original owner boundary
whether an external counterpart crosses a patch endpoint unsplit
```

Candidate and segment terminal fields are:

```text
containedBoundary=
candidates/exactValid/splitEquivalent/residualMissing/
externalUnsplit/underused/overused/ambiguous

containedBoundarySegments=
segments/exactValid/splitEquivalent/residualMissing/
externalUnsplit/underused/overused/ambiguous
```

`splitEquivalent` means the exact unsplit `TopologyEdgeKey` fails, but the complete segment is geometrically covered by exactly one retained-patch use and one correctly owned collinear counterpart. It remains diagnostic only; shadow topology determines whether the segmentation is actually manifold, and MG-R6B.1 does not weaken the original promotion gate.

The transformed clone also proceeds through shadow validation regardless of the exact-boundary result:

```text
containedShadow=
tested/overlapRemoved/topologyClean/tJunctionIncrease/
unexpectedOpenEdgeIncrease/sourceBoundaryIncrease/nonManifoldIncrease
```

The shadow observations are independent rather than terminal and therefore are not expected to sum to `tested`. This proves whether the planar subtraction worked and which topology invariant, if any, it worsened. Live construction, combined-candidate eligibility, readiness, rendered geometry, and `geometryCommit=disabled` remain unchanged.

Unity validation produced:

```text
containedBoundary=22/0/0/0/0/0/0/22
containedBoundarySegments=66/0/0/0/0/44/22/0
containedShadow=22/22/0/14/22/0/22
```

Every target overlap was removed, but no transformed candidate was topology-clean. All 22 gained unexpected open and non-manifold edges; 14 also gained T-junctions. The uniform three-edge signature was two underused segments plus one overused segment per patch. This rejects the exact-key-only explanation and proves that the owner residual plus adjacent boundary segmentation require correction.

## MG-R6B.2 — Bundled contained-boundary repair

MG-R6B.2 avoids another diagnostic-only round trip and applies both corrections directly in the clone:

1. Reconstruct the retained patch boundary as one deterministic oriented loop.
2. Identify its one contiguous owner-boundary run.
3. Replace that shared owner run with the reversed complementary patch path, producing an explicit notch rather than relying solely on the generic directed-segment arrangement.
4. Retain the generic arrangement as a deterministic fallback for any candidate that does not match the proven guided case.
5. Insert every authoritative patch endpoint into every transformed cloned face edge that spans it, without moving any point or changing surface area.
6. Classify residual-owner edge occurrences from the exact transformed record range rather than broad `SourceFaceIndex` equality.

```text

candidates/guidedResiduals/genericFallbacks/endpointAligned/
```

Terminal reconciliation is:

```text

```

`guidedResiduals`, `genericFallbacks`, and `endpointAligned` are independent observations. Existing `containedRepartition=`, `containedBoundary=`, `containedBoundarySegments=`, `containedShadow=`, and `containedCombined=` remain available so one Unity run validates both the repair and its exact failure mode if anything remains.

## Scope restrictions

The first commit-capable kernel supports:

- selected convex internal manifold edges only;
- one bevel segment;
- one solved width per source edge;
- replacement source faces;
- one bevel quad per selected edge;
- boundary-only deterministic triangulation for a closed selected corner loop;
- source-vertex-apex fan closure for an open selected run;
- explicit preservation of source boundary loops.

It does not support:

- rounded profiles;
- arbitrary segment counts;
- beveling source boundary edges;
- non-manifold input;
- post-hoc hole ownership;
- sampled ribbons or global cut planes.

## Why EW-B was retired

EW-B used the following sequence:

```text
independent face offsets
→ edge bridges
→ collect provisional open edges
→ infer source ownership from coordinates
→ reconstruct cap components
```

That direction was structurally backward. Generated geometry was asked to reveal topology that was already known in the source graph. It produced persistent open edges and T-junctions, and ownership classifications changed when geometry changed.

EW-C defines output topology first and solves positions second.

## Temporary topology representation

EW-C uses a small build-time half-edge layer. It is not a full Blender-style modelling system.

Each directed half-edge stores:

```text
origin vertex
destination vertex
source face
source undirected edge
next
previous
opposite
selected flag
```

This is sufficient to trace:

- source boundary loops;
- ordered face fans around a source vertex;
- contiguous selected-edge runs;
- explicit output corner ownership.

## Source boundary policy

Source boundary edges are traced before chamfer geometry. The first kernel never selects them for beveling.

A valid output preserves the same source-boundary identity. The final audit checks for additional boundaries rather than demanding zero total open edges.

## Single-edge geometry

For selected source edge `A → B` shared by faces `F0` and `F1`:

```text
d = normalize(B - A)
```

For face normal `n_f`, the in-face perpendicular is:

```text
m_f = normalize(n_f × d)
```

Its sign is corrected so it points into the source polygon.

For solved width `w`, the face-offset support line is:

```text
L_f(t) = A + w*m_f + t*d
```

The replacement rail on each incident face is obtained from the two replacement face corners at `A` and `B`.

The bevel strip is:

```text
A on F0
B on F0
B on F1
A on F1
```

This is one quad, later triangulated into two triangles if required.

## Face-corner solver

At source face corner `V`, the face is bounded by previous and next source edges.

- neither selected: preserve `V`;
- one selected: intersect its offset line with the unselected source-edge line;
- both selected: intersect the two offset lines.

The result is one explicit replacement point for `(face, source vertex)`.

No generated point is assigned later by nearest-distance ownership.

## Vertex-run closure

Incident half-edges are ordered around each source vertex. Selected edges are partitioned into contiguous runs.

### Closed selected loop

When the selected boundary segments form a closed loop around the source vertex, use only the ordered boundary vertices. A three-edge loop emits directly as one triangle. Larger loops project into an expected-normal basis and use deterministic ear clipping. No patch-centre vertex is created.

### Open selected run

When selected edges are bounded by unselected edges or a preserved source boundary, use the original source vertex as the crude apex and emit a fan over the ordered run.

### Multiple selected runs

Emit one independent crude patch for each contiguous selected run.

## Width feasibility

The first solver uses a conservative local bound:

```text
w_max(V) = 0.25 * min(adjacent source-edge lengths at V)
```

For selected edge `e=(u,v)`:

```text
w_e = min(w_requested, w_max(u), w_max(v))
```

A later refinement may solve less conservative geometric limits. The topology architecture does not depend on that refinement.

## EW-C0 readiness audit

EW-C0 emits no chamfer geometry. It proves that the source is suitable for the next stage by reporting:

- source graph validity;
- selected candidate mapping;
- directed half-edge count;
- source boundary-loop traceability;
- selected boundary/non-manifold exclusions;
- affected open and closed vertex fans.

Readiness blockers are:

- invalid source faces or edges;
- missing or mismatched selected graph edges;
- source non-manifold edges;
- source T-junctions;
- selected boundary or non-manifold edges;
- untraceable boundary topology;
- disconnected affected vertex fans.


## EW-C1 explicit corner solver

EW-C1 produces a build-time corner table keyed by `(graph face index, source vertex index)`. The table is authoritative for future replacement faces and selected-edge strips.

For two coplanar face lines

```text
p + t r
q + s k
```

with face normal `n`, the intersection parameter is:

```text
t = dot(cross(q - p, k), n) / dot(cross(r, k), n)
```

A near-zero denominator is an explicit corner-solve failure; EW-C1 does not guess ownership from nearby generated coordinates.

One width is solved per selected source edge. The proof-stage initial limit is the minimum of the requested width and 25% of every adjacent source-edge length at both endpoints and both incident faces. The same width is used at both endpoints.

Acute face corners can create a long miter even when the raw perpendicular offset is small. EW-C1R3 therefore performs up to twelve monotonic global passes. For a corner with displacement `d` and permitted displacement `d_max`, every selected edge participating in that corner is reduced by:

```text
scale = 0.95 * d_max / d
```

The reduced value is written back to the source-edge width, so both endpoints use the same width. The same pass also tests every unselected internal edge. If its two incident replacement faces retain no stable common interval, the solver gathers the selected edges controlling the four endpoint corners and uses a bounded binary search to find the largest stable common scale. The solve fails explicitly if either corner displacement or shared-edge overlap cannot be satisfied at the minimum stable width, or if the pass budget does not converge.

Unselected internal edges are reconciled in source-edge parameter space. Both incident faces receive the exact same endpoint `Vector3` values from the common rail interval. This is explicit source-edge ownership, not a generated-hole bridge.

EW-C1 validates:

- complete corner count;
- finite coordinates;
- conservative corner displacement;
- replacement-face area and winding;
- no collapse of previously stable source edges;
- exact/reconciled shared endpoints on unselected internal edges;
- stable span and length for every future selected-edge strip;
- preservation of the source boundary edges.

Geometry emission remains disabled.
